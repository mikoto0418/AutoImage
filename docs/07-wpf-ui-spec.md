# WPF 界面规格

## 设计原则

智图助手是生产工具界面，应保持安静、清晰、密度适中。界面不做营销页，不做装饰性英雄区，首屏直接呈现绘图工作台。

核心目标：

- 左侧快速输入。
- 中间稳定预览。
- 右侧结构检查。
- 底部集中操作。
- 状态和错误提示明确。

## 主窗口布局

```text
┌────────────────────────────────────────────────────────────┐
│ 顶部菜单：项目 / 导出 / 设置 / 帮助                         │
├───────────────┬─────────────────────────┬──────────────────┤
│ 左侧输入区     │ 中间预览区               │ 右侧结构区        │
│               │ WebView2 draw.io         │ JSON / 节点 / 边  │
├───────────────┴─────────────────────────┴──────────────────┤
│ 底部操作区：生成 / 修改 / 导出 draw.io / 同步 Visio / 保存版本 │
└────────────────────────────────────────────────────────────┘
```

## 左侧输入区

包含：

- 图类型选择。
- 自然语言输入框。
- 表结构文本输入模式。
- 图片上传入口。
- 生成按钮。

图类型下拉选项：

- 功能模块图。
- 流程图。
- Chen ER 图。
- 系统架构图。
- 层级结构图。
- 泳道图。
- 数据流图。
- 简化类图。

MVP1 中非前三项可以显示为禁用或标注后续支持。

## 中间预览区

默认展示 WebView2 draw.io 预览。

状态：

- 空状态：提示用户输入描述后生成图形。
- 加载中：显示生成和渲染状态。
- 预览中：展示 draw.io 编辑器。
- 失败：展示错误摘要和重试入口。

Visio 模式下，中间区显示 Visio 连接状态和最近同步结果，不替代 Visio 原生窗口。

## 右侧结构区

使用 Tabs：

- JSON：展示当前 Diagram JSON。
- 节点：表格展示节点 ID、名称、类型、形状。
- 边：表格展示边 ID、起点、终点、标签。
- 历史：展示版本快照和操作记录。

MVP1 至少实现 JSON 展示。

## 底部操作区

按钮：

- 生成图形。
- 应用修改。
- 导出 `.drawio`。
- 同步到 Visio。
- 保存版本。
- 恢复版本。

按钮状态必须根据当前上下文启用或禁用：

- 无 Diagram JSON 时，导出和同步禁用。
- Visio 不可用时，同步 Visio 禁用并显示原因。
- 生成中禁用重复生成。

## 设置窗口

配置项：

- API Base URL。
- API Key。
- 文本模型名称。
- 多模态模型名称。
- 默认图形风格。
- 默认导出目录。
- 超时时间。

API Key 不应显示明文，界面使用密码输入框。

## 识别确认界面

第四阶段使用。

功能：

- 显示原始图片。
- 显示识别出的节点列表。
- 显示识别出的边列表。
- 允许修改节点名称、类型、形状。
- 允许删除错误节点或边。
- 确认后生成 Diagram JSON。

## 页面状态

至少定义：

- `Idle`
- `Generating`
- `Generated`
- `Rendering`
- `Error`
- `VisioUnavailable`
- `ImageReview`

所有状态变化必须显示在界面，不允许静默失败。

## 验收标准

- 应用启动后直接进入工作台。
- 用户能在左侧输入并触发生成。
- 生成结果能在中间预览。
- 当前 Diagram JSON 能在右侧查看。
- 无 Visio 时界面不会阻断 draw.io 功能。
- 错误信息可读，不直接展示完整异常堆栈给普通用户。
