# 需求规格说明

## 功能需求

### 图形生成

系统必须支持通过文本生成结构化图形。文本输入包括自然语言描述、数据库表结构、业务流程说明和模块结构说明。

首版支持三类图：

- 功能模块图：使用层级矩形结构表达系统功能。
- 流程图：使用开始、处理、判断、结束等流程图节点表达处理过程。
- Chen ER 图：使用实体矩形、关系菱形、属性椭圆表达数据模型。

完整版本扩展支持：

- 系统架构图。
- 层级结构图。
- 泳道图。
- 数据流图。
- 简化类图。

### draw.io 输出

系统必须将 Diagram JSON 转换为 draw.io XML，并保存为 `.drawio` 文件。生成文件应能被 diagrams.net 正常打开和继续编辑。

WPF 客户端必须通过 WebView2 嵌入 draw.io 页面，加载生成 XML 供用户预览和手动微调。后续版本支持从嵌入页面读取当前 XML 并回写系统状态。

### Visio COM 输出

系统必须将 Visio 视为高级能力。未检测到 Visio 或未打开 Visio 时，系统不得阻断 draw.io 工作流，应提示用户仅使用 draw.io 模式。

Visio 能力包括：

- 检测本机 Visio 环境。
- 连接当前运行的 Visio 应用实例。
- 获取 ActiveDocument 和 ActivePage。
- 将 Diagram JSON 绘制为 Visio Shape。
- 写入 Shape 自定义属性，保存 Diagram JSON 节点 ID。
- 支持导出 Visio 原生文件、PDF、PNG。

### 自然语言增量修改

系统必须维护当前 Diagram JSON 状态。用户发出修改指令时，系统将指令转换为操作 JSON，而不是重新生成整张图。

必须支持的操作：

- 增加节点。
- 删除节点。
- 重命名节点。
- 增加边。
- 删除边。
- 修改边。
- 修改全局样式。
- 重新布局。

### 多模态图片识别

系统应支持上传截图、手绘图、旧系统图或论文插图。多模态模型识别结果必须先转换为 Diagram JSON 并进入确认界面，用户确认后才允许绘制或覆盖当前项目。

## 非功能需求

- 稳定性：模型输出错误不能导致应用崩溃。
- 可编辑性：输出结果必须是结构化图文件或 Visio Shape，不以静态位图作为主要结果。
- 可降级：Visio 不可用时必须保留 draw.io 主路径。
- 可追溯：自然语言修改和图结构变化必须保存历史记录。
- 可测试：Diagram JSON 校验、布局、draw.io XML 生成、操作 JSON 执行器必须可单元测试。
- 可配置：API Key、Base URL、模型名称、默认导出路径必须可配置。

## MVP 边界

MVP1 包含：

- WPF 主界面。
- 文本输入。
- 模型配置。
- Diagram JSON 类型和校验。
- 功能模块图、流程图、Chen ER 图。
- 规则布局。
- draw.io XML 生成。
- `.drawio` 导出。
- WebView2 预览。

MVP1 不包含：

- Visio COM 绘图。
- 自然语言增量修改。
- 多模态图片识别。
- 复杂自动布局算法。
- 多用户或云端同步。

## 风险约束

- 大模型输出可能不稳定，必须先做 JSON 校验和修复提示。
- draw.io 嵌入依赖 WebView2 Runtime，启动时需要检测环境。
- Visio COM 依赖本地 Visio 安装和当前打开页面，必须独立降级处理。
- 图片识别准确率不稳定，必须提供确认界面。
- 用户自然语言定位可能模糊，必须在操作执行前提供候选或错误提示。
