# 测试计划

## 测试目标

验证智图助手能够稳定完成 Diagram JSON 生成、校验、draw.io 输出、Visio 绘图、增量修改和多模态识别确认流程。

## 单元测试

### Diagram JSON 校验

用例：

- 缺少 `diagram_id` 时失败。
- `diagram_type` 不在允许值时失败。
- 节点 ID 重复时失败。
- 边引用不存在节点时失败。
- Chen ER 图关系节点不是 `diamond` 时失败。
- Chen ER 图实体节点不是 `rectangle` 时失败。
- Chen ER 图边存在箭头时自动修正或失败，具体策略由实现确定。

### 操作 JSON 执行

用例：

- `rename_node` 修改 label 后边引用不变。
- `delete_node` 删除节点后相关边被删除。
- `add_edge` 的 from/to 不存在时失败。
- `update_style` 可以将所有边改为无箭头直线。
- `relayout` 会更新节点坐标。

### draw.io XML 生成

用例：

- 每个节点生成一个 vertex mxCell。
- 每条边生成一个 edge mxCell。
- 矩形节点映射为矩形样式。
- 菱形节点映射为 rhombus 样式。
- 椭圆节点映射为 ellipse 样式。
- 默认样式包含白底黑线。

## 集成测试

### 文本到 draw.io

输入：

```text
生成一个学生选课系统 Chen ER 图，包括学生、课程、教师和选课关系。
```

期望：

- 返回合法 Diagram JSON。
- diagram_type 为 `chen_er`。
- 包含学生、课程、教师等节点。
- 生成 `.drawio` 文件。
- 文件能被 diagrams.net 打开。

### 功能模块图

输入：

```text
生成在线考试系统功能模块图，包括用户管理、题库管理、考试管理、成绩统计。
```

期望：

- diagram_type 为 `function_module`。
- 模块节点使用矩形。
- 父子层级清晰。
- 默认无箭头。

### 流程图

输入：

```text
生成用户登录流程图，包括输入账号密码、校验、成功进入首页、失败提示错误。
```

期望：

- diagram_type 为 `flowchart`。
- 判断节点使用菱形。
- 流程方向从上到下或从左到右。

## Visio 手工验收

前置条件：

- 本机安装 Visio。
- 打开一个空白 Visio 文档。

验收步骤：

1. 在应用中生成 Chen ER 图。
2. 点击同步到 Visio。
3. 查看 Visio 页面是否出现矩形、菱形、椭圆和连接线。
4. 检查连接线是否无箭头。
5. 检查 Shape 自定义属性是否包含 Diagram 节点 ID。

降级验收：

1. 关闭 Visio。
2. 点击同步到 Visio。
3. 应用提示 Visio 不可用。
4. draw.io 预览和导出仍可使用。

## 增量修改验收

用例一：重命名节点。

输入：

```text
把“用户管理”改成“账号管理”。
```

期望：

- 节点 label 更新。
- 节点 ID 不变。
- 相关边不丢失。

用例二：删除节点。

输入：

```text
删除“成绩统计”模块。
```

期望：

- 节点被删除。
- 与该节点相关的边被删除。
- 保存操作历史。

用例三：统一样式。

输入：

```text
把整张图改成论文黑白风格，所有箭头改成普通直线。
```

期望：

- fill_color 为白色。
- line_color 为黑色。
- shadow 为 false。
- 所有边 arrow 为 none。

## 多模态验收

步骤：

1. 上传一张流程图截图。
2. 系统返回识别出的节点和边。
3. 用户在确认界面修正一个节点名称。
4. 点击确认生成图。

期望：

- 当前项目不会被自动覆盖。
- warnings 可见。
- 确认后的 Diagram JSON 可生成 draw.io。

## 回归测试清单

- 生成失败后可以重新生成。
- 模型返回非 JSON 时不进入绘图。
- 导出路径无权限时显示错误。
- WebView2 加载失败时仍可保存 `.drawio`。
- SQLite 写入失败时内存中的 Diagram JSON 不丢失。
